HOG in six steps

Remember which invariance each step buys you, and the exam questions sort themselves out.

Step 01

Normalize & grayscale

Drop color, keep brightness. Gamma correction √I is optional — the later block normalization does most of its job.

Step 02

Compute gradients

Use the plain [-1,0,1] mask. Adding smoothing or switching to Sobel hurt performance — fine contours get blurred away.

Step 03

Orientation voting per cell

Inside each 8×8 cell, magnitude-weighted votes go into 9 bins (0–180°), split linearly between neighboring bins so small angle changes don't matter. → invariance to small shifts and deformations.

Step 04

Block normalization

Group 2×2 cells, normalize with L2-Hys, and slide the block one cell at a time. → illumination and contrast invariance. Each cell appears several times, each time normalized differently.

Step 05

Concatenate the descriptor

Concatenate every block vector into one 1-D vector: 3780 dimensions for a 64×128 window.

Step 06

Linear SVM + sliding window

Scan windows over several scales, compute w·x+b, remove duplicates with NMS. Being linear, each window costs one dot product — the secret to its speed.

Defaults from the original paper

Why 8×8, 9 bins, 2×2?

These values were chosen experimentally for pedestrian detection (INRIA). A different object class may need different numbers.

ParameterDefaultWhat happens if you change it
detection window64 × 128Includes a 16px margin around the person. Removing the margin hurts performance.
cell8 × 8 pxLarger → fewer dims and less compute, but fine contours are lost. Smaller → sensitive to noise.
orientation bins9 (unsigned)Little gain beyond 9. Clothing can be lighter or darker than the background, so unsigned works better.
block2 × 2 cellsSize of the normalization neighborhood. Too large dilutes local contrast.
block stride8 px (50% overlap)Removing overlap drops performance noticeably. Redundancy is robustness.
normalizationL2-HysL2, clip at 0.2, renormalize. L1-sqrt is similar; plain L1 is slightly worse.
descriptor dim37807×15 blocks × 4 cells × 9 bins.
Frequently asked

Common points of confusion

Q

How is it different from SIFT?

Both are orientation histograms, but SIFT is a sparse descriptor computed at detected keypoints and rotated to a dominant orientation, while HOG covers the whole window densely with no rotation alignment. People are mostly upright, so rotation invariance isn't needed.

Q

Why have both cells and blocks?

Cells set the spatial resolution; blocks set the normalization neighborhood. Because blocks overlap, one cell's histogram shows up several times in the descriptor, each time normalized at a different scale.

Q

Why do the lines follow edges, not gradients?

The gradient θ points where brightness changes fastest, i.e. perpendicular to the edge. Visualizations draw θ+90° so the lines read as contours.

Q

Why isn't it used much today?

CNNs learn the features themselves and overtook it in accuracy. But HOG's ingredients — local statistics, overlapping normalization, sliding windows — live on in modern detectors, which makes it worth learning as the prototype of the ideas.
